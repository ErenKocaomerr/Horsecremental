# MILESTONE 3 — THE REAL CORE GAME STRUCTURE

The goal of Milestone 3 is to make the game begin feeling like the actual incremental game instead of separate prototype screens.

The main gameplay structure should become:

**Stable / Farm / Upgrades**
↓
Horse automatically earns money from easy Training Races
↓
Player improves the horse
↓
Player attempts a difficult Main Race
↓
Main Race unlocks meaningful progression later

The Stable and Race areas should exist inside the **same gameplay scene/world**.

Do NOT use scene loading or teleporting between Stable and Race anymore.

This milestone should also improve game feel and introduce the first lightweight Farm system.

---

# 1. IMPORTANT — STABLE AND RACE MUST EXIST IN THE SAME SCENE

Currently Stable and Race may be separate scenes or may use scene transitions.

Change this structure.

The Stable area and Race Track should exist inside the SAME gameplay scene.

The player should be able to smoothly move/view between them.

There must NOT be:

- Loading screen
- Scene reload
- Teleportation effect
- Instant hard cut unless absolutely required for debugging

The game should feel like one connected place.

The player should feel that the race track exists next to / near the Stable.

---

# 2. CAMERA TRANSITION BETWEEN STABLE AND RACE

Use **Cinemachine** for the camera system.

Do not return to standard/manual camera systems unless technically required.

Create smooth camera transitions between gameplay areas.

Preferred interaction:

### Option A — A / D navigation

While in the Stable:

Press D → smoothly move camera toward Race area.

While at Race area:

Press A → smoothly move camera back toward Stable.

The camera should slide/pan smoothly rather than instantly teleport.

OR if the existing project architecture makes this cleaner:

### Option B — Arrow / UI Buttons

Use left/right arrow buttons such as:

< STABLE

RACE >

Pressing the button smoothly moves/blends the Cinemachine camera between areas.

Choose whichever implementation works best with the current project.

The important requirements are:

- Same scene
- Smooth transition
- Cinemachine
- No scene loading
- No player/world teleport feeling

Transitions should feel responsive and take approximately 0.5–1.5 seconds.

Do not make the camera movement painfully slow.

# 4. HORSE SHOULD BE ACTIVE WHILE WE ARE IN THE STABLE

This is very important.

The horse should NOT feel like it is doing nothing while the player is in the Stable.

While the player is managing upgrades / Farm / Stable systems, the horse should automatically participate in **easy Training Races** in the background.

These races represent the horse continuously racing against weaker opponents and earning money for the player.

This is the beginning of the game's idle / incremental income system.

---

# 5. IDLE TRAINING RACE SYSTEM

Create a simple automatic Training Race simulation.

This should NOT require rendering a full race every time.

Do not spawn a complicated full race simulation in the background if it is unnecessary.

A Training Race can be calculated/simulated using horse power/stat values.

Example loop:

Training Race Starts

↓

Training timer progresses

↓

Horse completes Training Race

↓

Coins are awarded automatically

↓

Next Training Race starts automatically

The horse should continuously earn money while the player is in the Stable.

Example:

TRAINING

Next Race: 8.4s

Estimated Reward: 35 Coins

When completed:

+35 Coins

Then automatically start another Training Race.

---

# 6. TRAINING RACE DIFFICULTY

Training Races are EASY races.

They exist primarily to generate money.

The player should generally succeed at them.

Do not make idle Training Races frustrating.

A very simple calculation is acceptable.

For example:

HorsePower compared against TrainingRaceRequirement.

If HorsePower is comfortably above the requirement:

Player automatically wins.

For Milestone 3, it is acceptable if Training Races are guaranteed to succeed.

The main purpose is passive income.

---

# 7. TRAINING RACE REWARDS

Training Races should give significantly less money than important Main Races.

Example prototype numbers:

Training Race:

20–50 Coins every 10–20 seconds

Main Race:

Several hundred Coins

These exact numbers should be configurable.

Do NOT hardcode balance everywhere.

Training income should make Stable activity productive without completely replacing Main Race rewards.

**"My horse is racing and earning money while I manage the Stable."**

If existing horse/environment assets make it easy to physically show the horse doing a short training loop, feel free to use them.

But functionality is more important than elaborate visuals.

Current Main Races are too easy.

Main Races should become actual progression gates.

They should feel like:

**"I am probably not strong enough yet. I need a few more upgrades."**

The player should NOT automatically win Main Races immediately.

# 11. DO NOT USE AGGRESSIVE RUBBER BANDING

Main Races should be difficult because opponents have strong, fixed stats.

Do NOT secretly scale every opponent to always match the player.

Do NOT make player upgrades meaningless.

For example:

Main Race opponent speeds:

Opponent 1 = 14.0

Opponent 2 = 14.5

Opponent 3 = 15.0

If player starts at:

Speed = 10

They should lose badly.

After upgrades:

Speed = 14+

They should become competitive.

Eventually:

Speed = 16+

The race should become noticeably easier.

This is essential for the incremental power fantasy.

# 15. REWORK THE BOOST SYSTEM

The current Boost system requires too much SPACE spamming and the meter behaviour does not feel good.

Replace/rework it.

Boost should use a **Boost Meter**.

The goal is to create a meter that the player actively manages and cannot simply keep permanently full.

---

# 16. BOOST INPUT

SPACE should add a SMALL amount of Boost Energy each time it is pressed.

Example:

Each SPACE press:

+5% Boost Meter

Do NOT instantly give a full large boost from one press.

Repeated presses gradually increase the meter.

However, avoid requiring extreme button mashing.

Tune values so moderate rhythmic pressing feels enough.

---

# 17. BOOST METER DRAIN

Boost Meter should continuously decrease.

Very important:

The higher the Boost Meter becomes, the FASTER it should drain.

Example behaviour:

0–25%:

Very slow drain

25–50%:

Slow/moderate drain

50–75%:

Faster drain

75–100%:

Very fast drain

This creates tension.

The player can push toward maximum speed, but maintaining near-maximum Boost should be difficult.

The Boost meter should naturally settle instead of sitting at 100%.

---

# 18. BOOST SPEED EFFECT

Boost should scale based on the current meter amount.

Example:

0% Boost:

No speed bonus

25%:

Small speed bonus

50%:

Medium bonus

75%:

Strong bonus

100%:

Maximum boost

Avoid binary:

Boost ON / Boost OFF

The speed change should feel smooth.

For example:

CurrentSpeedBonus = BoostMeterNormalized × BoostPower

Smoothly interpolate actual speed changes if necessary.

Do not make acceleration visually jerky.

---

# 19. BOOST SLIDER POLISH

The Boost UI slider should move smoothly.

Do not instantly snap UI values if avoidable.

Use interpolation / smoothing for the displayed slider.

Example concept:

Actual Boost = gameplay value

Displayed Boost = smoothly follows actual Boost

The bar should feel fluid.

Add lightweight visual feedback based on Boost amount.

Examples:

Low Boost:

Normal bar

High Boost:

Subtle pulse

Near Maximum:

Slight shake / glow / animation

Do not depend on custom assets.

Use UI scale, alpha, particles, animation, or existing assets.

This milestone is NOT about adding a huge amount of content.

The goal is to make the game finally feel like the real game.

**I am in my Stable doing incremental progression while my horse automatically earns money, then I look over toward the Race area, attempt a very difficult Main Race, lose, become stronger, and eventually return to beat it.**

Polish the feel of existing interactions instead of adding unnecessary features.
